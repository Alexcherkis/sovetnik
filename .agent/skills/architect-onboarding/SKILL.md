# 🏗️ Architect Onboarding & Project Mapping

Этот скилл активируется, когда нужно быстро и глубоко понять проект, в который я (ИИ) попадаю впервые, или когда нужно навести порядок в текущей структуре.

## 🎯 Цели
1. **Zero-Knowledge Entry**: Полное понимание проекта "с нуля".
2. **Standardization**: Приведение структуры папок и файлов к профессиональному виду.
3. **Actionable Roadmap**: Создание четкого плана действий (`PLAN.md`).

## 🛠️ Алгоритм действий (Workflow)

### Шаг 1: Техническая разведка (Deep Scan)
Я обязан провести аудит файловой системы:
- `ls -R` для понимания масштаба.
- Проверка `package.json`, `tsconfig.json`, `tailwind.config.js`.
- Поиск ключевых директорий: `src/`, `components/`, `pages/`, `public/`.

### Шаг 2: Анализ смыслов (Context Mining)
Я ищу и изучаю:
- Любые файлы `.md` (README, TECH_DOCS, ПЛАНЫ).
- Текст в компонентах (чтобы понять, что мы продаем).
- Конфиги API и систем аналитики.

### Шаг 3: Проектирование структуры
Я формирую или обновляю файл `PROJECT_STRUCTURE.md`, где описываю:
- Назначение каждой папки.
- Основные технологические решения.
- Местоположение критически важных файлов.

### Шаг 4: Интервью с Владельцем (Алексеем)
Если после шагов 1-3 остались "белые пятна", я обязан задать **3-5 точных вопросов** по бизнесу или логике.

### Шаг 5: Генерация Плана (`PLAN.md`)
Итоговый документ, который содержит:
- **Status Quo**: Что имеем сейчас.
- **Short-term Goals**: Что делаем в ближайшие 2-3 итерации.
- **Backlog**: Список задач на будущее.

## 📝 Правила коммуникации
- Тон: Экспертный, поддерживающий, дисциплинированный.
- Никаких предположений: Если не уверен — спроси.
- Фокус на Premium Web: Всегда предлагай решения уровня Apple/Cinematic.
